# Workshop and Demonstration Guide

## Outcome

Learners explain a source-grounded answer, identify its supporting record and demonstrate why a tool cannot approve its own proposal.

## Preparation

- Check Python and project dependency installation before the session.
- Start with the offline paths and supplied practice data.
- If a live exercise is planned, confirm account permissions, model availability, processing locations and a spending limit with the account owner.
- Choose one normal case, one missing-record case and one attempted unsupported action.

## Suggested sequence

1. Explain LLM, retrieval and tool-calling responsibilities using the delivery register and policy-handbook analogy.
2. Run the delivery assistant offline and show the retrieved policy IDs and structured answer.
3. Compare a model-generated answer only after the cloud account is configured; label the mode clearly.
4. Demonstrate an inventory proposal waiting for review and explain why review is separate.
5. Let learners run a second case independently and explain the result in business language.

## Assessment

- Does the answer identify the correct record and relevant policy?
- Does the learner distinguish a historical duration from a live ETA?
- Can the learner identify what was retrieved, what the model generated and what Python checked?
- Can the learner explain when human review is required?
- Can the learner reproduce a documented test and describe its limits?

Record learner completion and feedback only after an actual session. This guide contains no invented learner outcomes.
